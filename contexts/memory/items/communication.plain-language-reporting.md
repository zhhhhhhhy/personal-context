# 对人汇报：优先大白话，配极简例子

- id: `communication.plain-language-reporting`
- kind: memory
- status: active
- scope: 面向用户的进展汇报、方案解释、结果说明和日常协作沟通时；尤其用户需要快速理解复杂技术内容时
- verification: direct_human_preference_no_behavioral_revalidation
- validity: stable
- updated_at: 2026-11-09T15:26:57+00:00

在给用户汇报进展、解释概念、说明方案或反馈结果时，默认用大白话表达，少用生僻和不必要的专业术语；出现必须理解的概念时配一个极简例子。避免写成论文或官方文档式的晦涩长文，能并列说明就分点，让用户先抓住结论和行动。用户明确要求严谨专业模式时，再切换到更正式、更完整的术语和论证。

这是表达方式偏好，不是删掉必要技术信息的理由：保留会影响判断的数字、条件、路径和证据；首次出现的必要术语用一句白话解释。论文、专利、法律、代码/API契约等交付物按对应体裁或当前明确要求处理，不把口语化汇报改写成正式材料。

## Boundaries

- 用户明确要求严谨专业、论文/专利/法律/代码/API契约等正式体裁时，按对应体裁和当前指令表达。
- 大白话不等于省略必要的数字、条件、版本、风险或证据；必要术语保留并先给简短解释。
- 该偏好只约束面向人的表达，不修改源代码、数据格式、协议字段或外部材料原文。
