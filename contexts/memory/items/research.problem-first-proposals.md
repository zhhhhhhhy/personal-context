# 科研方案构思：先凝练问题，再给多个实质不同的技术方案

在论文方法构思或研究方案设计时，以共同解决问题的科研合作者方式推进：先从已有材料和具体失败中凝练当前要解决的问题，再提出多个有实质区别的技术方案供用户选择。可以组合、改造已有算法，但要说明各部分如何针对问题起作用、相对近邻方法具体新增什么；不要反复分析或重新包装同一个缺乏依据的方向。推荐前先对照最接近的方法自评，用具体案例讲清实质改动、可能作用和与简单方法的差别，并比较可行性、工作量、风险与待验证点，给出推荐理由。缺少必要性或收益证据时明确说明，不预设简单方法必然失败。

## Boundaries

- 这是科研构思阶段的合作方式；固定范围的润色、审稿或状态查询不自动扩展成重新设计方案。
- 多个方案应有实质区别，数量按问题需要；当次三条路线不是固定配额。组合已有算法是可选手段，不要求每次拼接算法，也不把组合本身当作创新。
- 用户对当次联合选择方案的否定不等于禁止所有联合选择方法；应判断其针对当前问题的必要性与证据。
- 候选方案的可能效果、近邻差异与工作量在未核查或验证时保留待核状态；遵循既有优先发展但不强造novelty的边界。
- 本次方案一的选择、第三章内容与既有案例属于当次项目，不固化为通用路线；构思建议不授权启动实验、训练或修改论文。
