# 复杂项目汇报：先定位任务；科研汇报精简重点并保留完整案例

在复杂工程或科研项目中，汇报进展或提出下一步方案前，先用一句简短的话说明当前任务处在整体流程的哪一环节、这一步解决什么问题，再报告结果、缺口和方案。必要时展示很短的流程链并标出当前节点，帮助用户保持对项目的把控。

涉及多个Agent或多次判定时，说明正在做原始评分、分歧处理还是事后复核，避免把不同阶段都笼统称为“复核”。沿用已有简洁汇报方式，不为定位任务添加长篇项目背景或固定大表。

这是用户明确要求今后记住的沟通方式；不证明任何研究或工程步骤已完成。

论文阶段性汇报的额外要求：先讲清为什么需要这项评测，再用精简的展示串起实验设计、关键结果、结果说明了什么以及新增认识；避免把大量过程文字平铺到汇报中。2026-10-26用户要求像PPT一样突出核心，同时明确“例子还是要全”。压缩说明文字时，保留支撑判断所需的完整代表案例和关键条件，不能只留口号或把所有案例删掉。

知识状态：真实用户明确给出的汇报组织与纠正要求。相邻助手展示过“字段要求→可见信息→应有行为→实际输出与判定”的案例结构，可作组织参考；本次未重新核验文档内容或科学结论，不据此证明效果已改善。

## Boundaries

- 简单问答或独立小修改不要求补画完整流程，也不强制每条回复都复述背景。
- 如果整体流程尚未核实，仅说明已知定位及不确定性，不编造完整任务图或当前进度。
- 定位用于解释当前工作，不授权执行下一阶段或重新启动历史任务；当前用户格式要求优先。
- PPT式精简与完整案例的组合仅用于论文/科研阶段性汇报，不要求论文正文、详细审计或所有日常回复一律按PPT组织。
- 保留完整代表案例不等于默认全量列出所有样本；案例应足以支撑当前判断，具体篇幅以当前任务为准。
- 汇报展示顺序不能倒写为真实研究时间顺序，动机实验与主实验的事实和作用仍按原材料区分。
