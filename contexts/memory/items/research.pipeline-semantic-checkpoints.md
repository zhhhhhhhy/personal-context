触发：数据构造、参考标注、生成与评分之间出现字段含义、输入或结论衔接不一致，用户难以判断问题来自哪一层。

| 阶段 | 输入 → 产出 | 关键判断 |
|---|---|---|
| 定位检查点 | 当前实际流程及各步材料 → 节点、输入输出与检查对象 | 先讲问题在哪个环节，再提出处理方案；流程未知部分保留待核 |
| 样例展示 | 相关节点的代表性样例 → 可检查的字段、上下文、参考及下游接收内容 | 让用户看具体材料；不默认要求逐项全量审核 |
| 源头溯查 | 具体疑点及生成/构造prompt → 语义或协议变化发生的位置 | 同时核对题目、字段、可见材料、参考和评分输入；不只凭一段抽象解释判错 |
| 确定修复范围 | 同类风险排查结果 → 单例修复或同类问题处理范围 | 先确认是否仅一个问题；不把某个例子的措辞硬编码成全局prompt规则 |
| 关联验证 | 限定改动及受影响下游 → 本次确已检查和仍未检查的部分 | 保留旧记录、来源及边界；修复一例不代表全链路正确 |

多节点可由本人或按当前任务授权的Agent检查，但Agent判断不能冒充真人金标；已有审核Skill和独立初判规范继续适用。本条不自动触发Agent派遣或实验。

## Boundaries

- 这是出现实际链路疑点时的局部流程，不要求每个科研任务先做全链路检查或默认全量独立复核。
- 样例检查不等于总体质量认证；没有看到原始材料时保持待核，不能据助手报告认定语义错误或修复成功。
- 原项目题号、分组数量、模型和具体争议裁定不作为其他任务默认口径。
- 对Agent职责、原始初判、事后裁定和评估公平性的已有规范不在此复制；当前任务授权与隐私边界不变。
