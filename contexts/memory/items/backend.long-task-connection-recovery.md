知识状态：用户要求的运行故障修复方法，附历史实现、诊断和局部恢复证据；不保证所有服务、睡眠或超时故障已解决。

触发：本机CLI或API编排的长任务，出现睡眠恢复、连续连接失败或Core调用超时。

1. 先按调用阶段区分传输/路由失败、模型容量不足、Core超时与交付后的功能缺陷，保留原始错误和既有结果；不把所有超时归因于睡眠或网络。
2. 开始长任务及恢复后检查连接。HTTP可达只证明传输层可达；恢复并发前，在当前授权和原预算内用单路真实调用确认实际通道。
3. 连续传输故障时暂停后续派发并保留待处理进度，给出可观察的状态和恢复入口。检查后先单路恢复，再放行后续调用；已结束任务不因恢复按钮自动重新生成。
4. 先验证受影响的开发路径，再按原验收范围续接；保持数据、模型、预算和旧结果，不能通过加调用配额、改题号或消耗未授权集合宣称修复。

历史证据：同源工具L3707列出共享连接状态及单路恢复条件；浏览器L3754实际显示暂停与“检查连接并继续”；工具L3854报告真实读写诊断成功。L4143结果仍含模型容量失败与发布后功能缺陷，因此连接恢复不等于交付全部正确，也不证明省时或省钱。当前任务未重连服务或重跑评测。

下次复用的是分层定位和暂停/恢复顺序；阈值、退避及预算沿用当前项目契约，不照抄原项目常数。

## Boundaries

- 历史改进仅针对该CLI编排样例；本条不是所有后端系统必须采用的统一架构。
- 传输可达、真实调用成功、Core完成、发布及业务验收是不同证据层；不能互相替代。
- 阈值、端口、超时和预算依当前项目约定，不照搬历史值；不扩大重试或执行授权。
