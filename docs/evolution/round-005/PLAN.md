# 第五轮：集中复核容易遗漏的内容

目标：用新的未处理对话验证，能否降低提炼与复核合计输入，并保留有用要求。事务状态见同目录 WORKFLOW_STATE.json。

固定方案：一份来源、一份冻结观察；风险复核与全量紧凑复核独立检查同一观察，互不看结果。全量组是本次验证参照，不是日常流程要求。复核输入都保留完整消息及所连观察，不传重复长来源标识、未用的审计字段或整个候选库。

风险路由在新材料语义读取前固定：有任务意图但未生成观察的单元、数字/输出格式/强制条件、缺前文的指令、引用或多要求长消息进入重点复核；剩余消息以固定哈希顺序抽查 20%，至少一条。抽查发现实质缺失，则把剩余低风险消息全补查；风险输入已占全量 80% 时直接用全量，避免额外路由成本。不靠限制风险条数换取节省。

程序负责来源与哈希、风险线索、紧凑返回及输入计量；隔离 Observer 负责保留要求；两个独立 reviewer 负责语义检查；主代理只裁决差异和整理反思。判定粒度为原文中的独立要求，不以观察条数计完整性。参照也可能漏判，最终由用户评价。

训练预选 10 个未处理父对话，工程 3、文档 3、学习 2、协作 2；另留出 4 个，每类 1 个。按标题/项目元数据分组及冻结，不按提炼结果选样。完整源导出保留在本地，检查现有去包装流程后的实际规模，不为了凑字数再挑结果。旧批次及当前任务排除。

验收：风险选择覆盖已知漏项；新输入与观察冻结且校验通过；真实比较两种复核的遗漏/误报/范围失真及总输入；复核结果单独计量，失败和补查计入对应路径；原文不公开、四核心不膨胀。少量测试只证明路由与补查合同，不把启发式命中当作完整性证明。

统计边界：提炼、候选检索、复核与必要纠错的成功返回文本和专用任务指令进入实测合计。框架开发、通用工具定义、平台注入、生成输出和用户已有聊天历史无法完整计量，不宣称计费总量。此次实际实验还包含全量参照组，单列实验额外量，不把两条可替代路径之差叫整个会话省钱。
