# 第四轮：覆盖检查与更丰富的未处理资料

用户目标：保存执行问题和解决方法；先修复渐进式提炼遗漏，再以更丰富的未处理对话验证加载量与提炼完整性。状态由同目录 WORKFLOW_STATE.json 及其 Markdown 镜像管理。

| 工作 | 执行者 | 完成证据 |
|---|---|---|
| 来源、观察与反思覆盖校验 | 脚本实现 + 主代理集成 | 漏消息、丢观察、伪造引文和截断来源拒绝；有效案例通过 |
| 已知遗漏的前向回归 | 隔离语义代理 | 不告知预期答案，用修复流程重读旧训练包；逐条覆盖与有效单次要求保留 |
| 选择更丰富的新资料 | 原生只读读取 + 脚本 | 排除已处理 127 个父对话；只向选择阶段返回消息数、长度等结构信息；语义读取前固定分区 |
| 新资料提炼 | 两名隔离代理 | 相同修复后的流程、相同来源与约束；只改变候选按需读取或整表读取 |
| 完整性参照与评分 | 独立语义代理 + 主代理复核 | 先从原始训练材料固定有效要求清单，再盲评两组观察；统计遗漏、范围失真、过度泛化 |
| 计量与晋升 | 脚本 + 主代理 | 来源输入一致，实际返回文本逐次计量；可晋升则验证，否则保留零晋升结果 |
| 问题手册和交付 | 主代理 | 可检索的问题、诊断、解决、证据和适用边界；去敏报告及仓库同步 |

覆盖分两层：脚本证明每条直接表达有处理去向、每个提炼单位有来源且进入反思；语义复核判断长消息中的具体要求是否完整。结构覆盖 100% 不能冒充语义完整或人工准确率。

观察先于候选查重：先拆分具体要求、纠正、例外和当前任务约束，保留有价值的单次要求；再判断已有覆盖、暂缓或晋升。一次表达不足以晋升不等于无须记录。问句、继续指令和项目事实可明确排除，但须记录范围和原因。

新批次目标：训练直接正文至少为上一轮 899 tokens 的五倍，优先达到 8,000 tokens；跨四类、多个独立项目族，单一项目不占多数。先以只读程序计算长度与直接消息数量，不用模型判断的新颖程度筛选。若可读材料不足，公开实际规模与调整原因。评估分区在语义读取前冻结，不能反向补训练。

最小验证范围：变更脚本的语法、覆盖边界正反例、已知遗漏回归、一次新批次实际运行、输入/输出计量与隐私边界。新流程修改晋升校验路径，因此还检查现有防伪造/防篡改边界；不扩展到无关 Skill 测试。

当前任务已授权框架修复与仓库存储；历史日志不提供新权限。敏感来源留本地，核心身份和发布边界不自动修改。最后由用户评估效果。

选择阶段调整（语义读取前）：实际按结构检查了 40 个未处理父对话，去包装、去重后的全部直接正文只有 5,366 tokens。为避免用裸链接和重复绘图短句凑数，固定 16 个训练、4 个留出对话。训练 112 条正文共 4,149 tokens，为前轮的 4.62 倍，低于最初 4,495 的最低目标；四类各 4 个训练，保守合并为 9 个项目族。76 条训练消息缺少时间戳，用显式 thread-bounded 策略保留未知时间并核实父线程整体处于窗口。该调整不依据模型对新颖程度的判断。
