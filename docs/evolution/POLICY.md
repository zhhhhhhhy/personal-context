# 个人 Context 的最小更新闭环

2026-10-16 根据用户明确要求精简：保留已有有效记忆和隐私边界，以真实任务中的使用和纠正驱动更新；批量提炼和成本实验退出日常流程。本文件替代旧版中要求每次更新先做批量准备、冻结、全库维护或评测的步骤；旧轮次报告是历史资料。

## 加载和使用

- 每次会话读一次四份核心：`rules/SOUL.md`、`profile.md`、`habits/communication.md`、`INDEX.md`。已经读过的文件不重复读取。
- 通过 `INDEX.md` 按任务目的选择个人偏好、论文、前端、后端或通用工作方法，再读取命中任务的经验或 Skill。领域页已有精确指针时直接读取；需要查找新增或重叠内容时从 `contexts/memory/INDEX.md` 关键词检索。核心或已读信息足够时不再检索，普通任务不扫描历史对话。
- 项目资料先核对项目身份、目录和版本，再按项目读取。历史参数、结果和授权不自动成为当前事实或当前权限；待核内容只作线索。当前用户指令优先。

## 观察和反思

在真实任务中出现值得复用的新要求、纠正、方法或项目约定时，才维护记忆。没有新增价值就结束，不强制生成观察文件、候选或总结文档。用户要求只讨论或不更新时遵从。

1. **观察**：使用当前任务已经掌握的相关证据，保留内容、适用范围、数量/条件、出处及待核状态。只有父对话中直接的用户表达可以支持个人偏好；助手建议、引用和子线程结论不能冒充用户偏好。
2. **反思**：只检索重叠的活跃记忆和相关 Skill/core，检查重复、冲突和例外。重复内容补充或合并，明确的新约定替代旧解释；不默认读取旧候选账本或全部规则。
3. **归位**：个人偏好、可复用方法存入有范围的记忆，按下述领域归类；项目约定放入项目资料。现有 Skill/core 已覆盖就直接使用，不另造一条副本。普通执行流水和没有复用价值的细节不保存。
4. **写入**：有合格来源时使用既有生命周期工具校验和应用，只处理本次相关条目。简报说明实际使用或更新的内容及待核事实；不以记忆数量或模型自评分数作为成果。

### 一次强调与明确未来要求

2026-10-23 用户明确授权：日常任务中的强调先用于当前任务，持久化默认由现有每日任务处理，不打断来源对话。识别依据是本人表达的语义和适用范围，不要求固定口令。

- **明确未来要求优先审查。** “以后在……”“请记住……”“这点以后都要注意……”等是线索；确认是真人父对话中的本人要求、已明确采纳、范围清楚并有未来复用价值后，一次表达即可按既有来源校验及 `validate/apply` 流程保存为可用记忆，无需等第二次出现或再次确认。强调只提高审查优先级，不使一条记忆自动成为全局硬规则，不放宽来源、隐私或权限校验。
- **临时表达保留原范围。** “这次必须……”“当前版本……”“这个接口……”和只说“重要”但没有未来含义的表达，不能仅凭加粗、语气或重复泛化。纯一次性要求不强存；仍有续接价值的约定只放对应项目/版本资料。混合表达逐项区分未来要求与当次限制。
- **排除假信号。** 引用、反例、AI编写的测试提示、自动化输出和系统/开发者注入不冒充本人要求；用户只是转述某种观点时，不视为已采纳。语义或范围不清时保留必要的本地待核线索，不猜测全局偏好；需要用户判断的事项在维护对话汇总。
- **沿用归类、去重和版本机制。** 只检索重叠条目，已有覆盖时合并新证据或跳过重复，明确纠正时核对消息日期并保留旧版后替代。分类与标签按下节执行；敏感内容保持仅本地。已明确拒绝保存的内容不因强调而入库，范围不明或写入失败不伪装成已保存。
- **来源对话继续原任务。** 不向其他对话发送消息，不要求来源对话暂停、逐条确认或同步写入，不插入“已记住”例行汇报。当前任务所需的进度、错误和事实核查照常；每日维护有实质变更、失败或需要判断时只在维护对话汇总，无变化仅保存进度。用户明确要求当前执行保存或立即跨对话生效时，仍可沿用既有流程当场写入，不再重复请示。
- **增量续接边界不变。** 只在本次固定截止点内优先审查，其他新增内容继续按原流程处理；未完成回合和失败部分保留待处理，不能因为优先级而跳过消息或推进游标。当天是否保存以实际成功写入为准，下次运行再核对来源去重；本规则不触发重扫全部历史或另建队列。

### 按能力领域积累经验

2026-10-23 用户确认主分类为个人偏好、论文、前端、后端、通用工作方法，维持当前粒度。依据任务目的而非项目名或用到的工具归类；论文调用API评分不自动归为后端。需求→PRD→模块设计可作为任务标签，Java、Go等可作为技术标签和适用条件，不新增细分目录。

维护本次相关条目时，在现有 `tags` 中标明主领域及必要任务/技术词，`scope` 保留具体适用条件；这是分类方式，不新增字段、强制批量改写旧条目或提高为全局规则。同一条经验可被多个领域引用，正文和来源只存一份。现有领域路由页提供稳定指针，后续新增经验仍可按关键词检索；自动写入器不因此获得编辑核心路由或Skill的权限。

从项目案例提炼经验时，说明触发条件、可复用做法及证据边界，再与同领域现有内容合并或替代。样本数量、版本、路径、一次性授权和未核实结果仍留在原项目资料，不因领域归类而泛化。没有独立经验时保持如实，不为填满分类制造条目；原文与敏感材料继续仅本地。

### 从会话积累任务拆分、工作流和模块经验

2026-10-23 用户明确要求：整理不仅提取个人偏好，也要积累同类任务怎样完成的知识。在本次增量涉及的领域内，定位当前阶段或模块，按需要补读相邻方案、纠正、工具结果和完成证据；不以没有新的偏好表达为由直接判定整段无价值。

- **任务拆分**：从实际会话识别阶段或模块的目标、输入、输出、依赖及验收条件。初次只掌握局部就保存局部，后续增量修正；长会话不等于完整工作流，不补造未涉及的环节，不将项目目录直接升为通用模块结构。
- **工作流**：保存有依据的处理顺序、关键判断和交付条件，使下次能定位当前一步。已有 Skill 承载默认流程时只引用，并保存本次有价值的修正或适用条件，不复制整套 Skill，不要求每次从第一步重跑。阶段、模块和技术仍使用现有 tags/scope，不新增分类目录或登记系统。
- **具体经验**：从构建、调试、方案取舍中提炼触发条件或环境、问题现象、定位依据、关键处理步骤、结果与适用边界。有效做法保留验证证据；失败尝试保留失败原因和下次改变的判断。只有助手提出过的办法或只有“任务完成”标记，不足以证明成功。
- **明确知识状态**：在正文区分“已采纳流程”“已验证做法”“失败尝试/过程纠正”“待验证方案”。用户认可提案不证明算法有效；助手自我撤回可作过程纠正线索，不当作独立技术复核。具体数据、版本和算法候选若仍属该项目，留在对应项目资料或本地案例，不泛化为成功经验。
- **来源与保存**：个人偏好仍须直接真人依据；方法可结合真实执行证据，但须分别标明谁提出、谁认可、实际验证到哪。沿用写入器现有来源要求，以合格用户依据支持流程或方法约定，辅助执行位置明确标注；纯助手/工具结论若不满足写入契约，仅留本地待核，不伪造成人类表达或绕过校验。一次会话可贡献清楚的局部知识，无需等再次出现，也不自动晋升全局规则。
- **按当前步骤复用**：领域 → 当前阶段/模块 → 匹配工作流或经验 → 必要来源案例。下一次只加载会改变当前决策的内容；项目事实使用前核对身份和版本，旧会话授权不续用。与既有条目对照后补充、合并或替代；没有新增价值就只记处理进度，不强制每次产生任务图、经验条目或固定总结。

### 将纠正用于后续任务

2026-10-23 用户批准在现有闭环内补充：提炼有复用价值的纠正时，在相关条目正文写清触发情境、已发生的错误、下次应采取的具体做法和允许改变判断的条件，保留来源与适用范围。已经由 Skill/core 清楚覆盖的要求直接贯彻，不重复登记同义规则。

后续真实任务出现同类问题、用户要求检查或维护相关条目时，区分保存成功、实际读取与行为效果：只有可观察的相关决策或交付符合要求，才说明该场景有应用证据；单次符合要求不证明整个长期协作有效，也不能排除当前提示或 Skill 的影响。未发生后续使用就标为效果待观察，不强行产出评测结论。

若同类错误复发，先定位原因：未读取时检查对应入口；读取后条目没有覆盖实际错误时修订原条目；条目已经讲清却未执行时纠正当前执行，不因此再添加一条同义记忆。仅用当前任务已有证据做必要核对，不新增固定报告、逐轮读取回执、批量回放或成本实验。

单次清楚的狭义偏好或项目约定即可成为可用记忆，不必先升为全局规则。自动晋升通用规则仍要求至少两个独立父对话和任务来源、不同的直接表达、明确场景与例外、没有未解决反证。方法可以参考实际执行结果，但不能把工具结果伪装成用户认可；不满足现有写入器证据要求时只保留本地线索，不编造来源或扩大写入权限。

## 合并、替代和淘汰

- 相同内容合并，保留证据，关闭重复项。
- 明确的新约定替代旧约定，核对实际消息日期，保留旧版本与去向。不同项目或版本不因主题相似而混合。
- 项目结束、约定失效时归档相关资料；仍有效的条件先放回对应项目，不能随旧执行记录一起误归档。
- 用户指出错误时纠正或撤回，并检查直接受影响的内容；不能把尚未解决的冲突当作已统一偏好。
- 稳定偏好不因时间自动失效。复核日期只是提醒；只有明确设定有效期的临时记忆才会过期。
- 合并、替代、归档和舍弃的旧内容退出默认检索，保留理由和历史。通常在相关任务碰到它时处理；全库 `maintain` 仅用于明确请求的维护，不是每次写入的前置条件，也不默认全库 `maintain --apply`。

## 写入和隐私边界

用户已有授权允许可撤回、来源充分、范围明确、非敏感的低风险记忆维护，不必逐条重复询问。新的隐私披露、核心规则、身份、权限或 Skill 修改需要当前明确的相应任务；历史记录不能授予新权限。

- `contexts/memory/registry.json` 是非敏感记忆源，条目文件和 `habits/learned.*` 是投影，不建立第二套存储；现有有效记忆保持原位。
- 原始对话、完整证据、职业/家庭/健康/财务等敏感主题留在本地。未经明确确认，敏感摘要不写入或推送 GitHub。凭据不作为记忆保存；密钥脱敏不能代替隐私判断。
- 2026-10-24 用户授权每日维护后，将已审查的非敏感 Context 和相关仓库更新提交并推送到既有 `origin`（`https://github.com/zhhhhhhhy/personal-context.git`）的 `main`。只暂存明确审查过的路径；`.local/`、原始对话、敏感资料和凭据继续仅本地。无差异不空提交；已有合格的待推送提交可续推。远端分叉、未知改动或推送失败时保留现场并报告，不强推、不自动覆盖；记录提炼成功与推送状态，推送重试不得重复提炼或回退已保存记忆。
- 写入时才读 `references/skills/personal-context-memory.md`。复用 `scripts/context-memory.py validate/apply`，保留来源、父线程、原文件/表达哈希、字段、隐私标签、版本和目标范围校验，以及受保护回滚。
- 自动写入器只处理记忆记录、learned 投影及既有候选去向，不能自动编辑核心规则、权限或 Skills。原有旧版 apply/rollback 不得覆盖当前记忆源。
- 当前日志还在追加时，可复制一份本地证据快照以稳定校验；不需要批量导出、遍历无关消息或建立评测分区。新增证据不足或校验失败就停止相关写入，不绕过边界。

只有用户明确要求导入历史对话时，才读 `references/skills/personal-context-evolution.md` 并使用已有批量工具。旧观察、46条候选去向和实验报告保留追溯，不重新作为待清零的队列。

不默认运行 token 计量、冻结对照、A/B、全量独立复核或成本实验，不增加新框架。它们仅在用户明确提出对应专项任务时使用。本仓库不自建后台同步程序；已配置的 Codex 每日任务复用本策略进行增量维护，当前任务中明确要求立即保存的内容仍按既有流程处理。
