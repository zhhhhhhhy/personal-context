# 自进化规则

## 授权与范围

2026-10-14 用户要求建立自进化功能、用历史对话试跑，再由用户评估。该授权替代过去“所有候选逐条人工批准”的门槛；仅适用于可撤回、非敏感、有充分证据的协作经验。历史日志、子代理和模型自评不能授予新权限。

每次会话常驻核心：`rules/SOUL.md`、`profile.md`、`habits/communication.md`、`INDEX.md`。画像详情、Skill 正文和 L1/L2 历史按任务读取。可用记忆从 `contexts/memory/INDEX.md` 路由；长期规则投影见 `habits/learned.md`，不自动膨胀核心。

2026-10-15 用户进一步授权参考原项目，落地可用记忆、合并、替代和淘汰，并裁决现有46条。`contexts/memory/registry.json` 是非敏感记忆源，敏感主题仅在 `.local/context-memory/`；`habits/learned.*` 是长期规则投影。当前这次明确的 Skill 合并可以修改相应 Skill；历史自动进化仍不能任意改写核心或其他 Skill。

## Observer：记录，不改规则

- 按日期、父对话和消息指纹增量处理；源日志只读。每批冻结输入哈希及训练/复核分区。
- 查旧候选前，先逐条建立来源到具体要求、观察的对应关系；有价值的单次要求也保留。新批次必须通过来源覆盖与观察去向校验。结构覆盖不证明语义完整，完整性比较另做独立原文复核。
- 区分直接用户表达、引用资料、助手建议、工具输出和运行时包装。只有父对话中直接用户表达能支持个人偏好；子线程最多支持过程或失败分析。
- 保留具体出处、适用范围、反例和不确定性。单次要求不升级成“永远如此”。记录需要保留的上下文，避免把“先讨论这个方案”改成“所有修改都必须先问”。
- 首轮提炼不能因内容待核实而删去任务相关的具体数量、对象、条件分支或来源。观察中同时写清具体内容、谁提供、出处和待核状态；引用建议不等于用户采纳，用户陈述不等于已证实事实。冻结前按这四方面做一次原文对照，按独立检查点拆分；该自查不增加默认全量独立复核。
- 密钥脱敏不等于隐私审查。职业、家庭、健康、财务等敏感细节及包含私密主题的观察只留本地；不得凭“confidence=high”发布。

## Reflector：合并、限定、晋升

- 先查活跃记忆、core、Skill 和候选去向。每个有效观察明确进入可用记忆、已有覆盖、通用规则或舍弃；只有真正缺少判断依据才暂缓。不要用换句话说新增同义规则。
- Reflection 必须显式记录 `conflict_check`：是否检查 core、learned 和 candidate ledger。缺少冲突检查时即使证据数量足够也不得应用。
- 单次明确的项目约定或狭义场景偏好即可保存并按需调用，必须保留范围、具体条件、出处和待核状态。通用规则自动晋升才需要至少两个独立父对话、不同直接表述和独立任务来源、明确例外、没有未解决反证，并通过隐私检查。重复粘贴、代理转述和助手建议不算独立偏好支持。
- 用户一次明确的当前指令可直接修改框架，但不能伪装成从历史中学习的结果。本次规则移植与历史进化分开统计。
- 未解决冲突、只有助手表达、无法区分引用与用户采纳时收窄、暂缓或舍弃；不补造个人事实。提问、写作请求和用户陈述不能自动变成已验证结果。
- 合并保留证据并关闭重复项；替代必须指向新的明确解释，旧条目保留版本和去向。归档/舍弃停止活跃调用，保留理由和源日志。到复核日期只提示检查；稳定偏好不因年龄自动失效，只有明确有效期的临时记忆会自动过期。
- 每次请求进化先运行 `context-memory.py maintain`，检查到期复核与临时过期，再处理新增内容。语义合并、替代和淘汰由当前任务决定，脚本执行边界和回滚；没有后台调度。已处理观察退出活跃队列。46条最终去向见 `notes/candidate-dispositions.md`，不再作为待审积压反复计入新发现。

## 应用与边界

`scripts/context-evolution.py prepare` 保留原有增量取证能力。新写入由 `scripts/context-memory.py validate/apply` 校验来源、原始文件哈希、父线程、字段、隐私标签及当前版本后，只更新记忆记录、learned 投影和候选去向。模型不能给它任意目标文件路径；原有 apply/rollback 不得覆盖已初始化的新记忆源。操作契约见 `references/skills/personal-context-memory.md`。

核心规则、身份与价值观、隐私边界、外部发布权限及修改其他 Skill 都不由这个自动写入路径处理。需要改动时由当前用户指令决定。自动应用不等于用户认可；用户可纠正或要求回滚。回滚若发现后续修改会拒绝执行，先解决冲突。

模型的语义复核是判断而非数学证明。脚本负责可验证边界，不能证明一句话足以代表用户。最终报告必须展示实际证据强度与局限。

## 触发方式

对 Codex 说“用最近一周未处理的对话进化 Context”，或调用 `$personal-context`。当前会话完成两阶段推理并调用脚本。系统已具备按需自进化流程；每日 Observer / 每周 Reflector 可作为运行节奏，但未创建定时任务。触发、自动应用和后台调度是三个不同状态。
