# 渐进式 Context 加载与维护

2026-10-15 根据用户直接要求建立；这是框架维护约定，不是历史对话自动推断的偏好。

## 加载顺序

1. 每次会话只读一次四份核心文件。先看索引，再选当前任务的主题或 Skill。
2. 入口只保留用途、触发条件、必要约束和下一层路由。详细流程按阶段读取；例子、证据和旧版本放在按需引用中。
3. 先检索命中条目或相关片段。只有当前信息不足、存在冲突或任务进入下一阶段时才深入；不因目录可见就递归读取，不重复整份返回已读文件。
4. 历史候选先读 `notes/candidates.md`；已知 ID 用 `show-candidate --id` 精确读取单条，未知时读相关主题或跨主题检索。拆分不改变候选状态，确定性校验可扫描全部 ID。
5. 新经验继续按进化 POLICY 处理。`habits/learned.md` 达到入口预算前，应建立主题索引和条目文件，并先适配应用及回滚流程，不能只把大文件换个路径后仍默认全读。

## 预算与检查

统一使用 `o200k_base` 估算文件正文；它不是当前模型的精确计费分词，也不包含工具、系统提示和聊天历史。

- 四份核心合计不超过 2,000 tokens。
- 每份 `SKILL.md` 不超过 1,000 tokens；候选总入口不超过 600。
- 候选主题页不超过 2,500 tokens；learned 入口不超过 1,000。
- 详细参考没有统一总量限制；超过约 3,000 tokens 时，优先用目录、标题或关键词定位片段。

维护入口、规则或候选结构后，运行 `python scripts/context-budget.py`；同步 Skill 前也会检查。具体阈值在 `docs/context-loading/budgets.json`，不得为了让检查通过而随意提高。确需调整时记录原因和用户任务要求。

压缩入口必须保留必要行为、来源、范围和异常边界。先合并仓库与运行时差异，再同步完整包。验证入口预算、链接、记录保留和实际路由后停止；token 下降本身不证明任务质量提高。
