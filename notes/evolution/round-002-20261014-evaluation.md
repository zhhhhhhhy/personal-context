# 第二轮 Context 进化：分类比较结果

完成日期：2026-10-15（Asia/Shanghai）。批次在前一天冻结，保留编号 `round-002-20261014`。

**本轮完成了分类提炼和新回答对比，但没有发现值得新增的长期规则。** 结果为：补强 3 项已有原则的证据，暂缓 4 项，拒绝 1 项过度泛化，新增 learned 规则 0 条。框架的证据筛选和应用校验得到改进；内容带来的额外收益尚未证明。最终效果由用户评估。

## 哪些内容没有进入长期 Context

| 观察 | 处理 | 原因 |
|---|---|---|
| 调研必须先交代研究进展、未解决问题，再给计划 | 暂缓泛化 | 多个请求来自同一课题，而且现状与缺口本来就是相关研究 Skill 的职责 |
| 科研评审始终采用严厉导师式批判 | 暂缓泛化 | 当次评审要求成立；不证明所有研究或交流都偏好严厉语气。独立判断已有核心规则覆盖 |
| 文档复制或转换总要附带生成脚本 | 暂缓 | 只有一个独立情境，也可能是当时学习实现方法的需要 |
| 讨论产品总要优先考虑本机硬件与部署 | 暂缓 | 只有一个主题，设备事实也可能过时 |
| 所有实验都固定每个难度重跑三题 | 拒绝 | 同一任务的重复请求，数量属于当次实验要求 |

这些判断只决定是否将观察泛化为默认规则。当次用户明确提出的要求，仍应正常遵从。

## 新回答比较如何进行

先固定训练与评估对话，再只读训练材料形成候选。唯一进入对比的候选是“明确比较概念时，先回应点名的区别维度”。候选措辞在打开评估正文前冻结，评估后没有调词重测。

两名隔离的生成代理分别收到相同的四个核心 Context、对应任务的当前 Skill 摘要和八个情境；其中一方额外收到候选规则。各生成 8 个新回答，共 16 个。独立评审者只见每题随机排列的 X/Y 答案、题目事实和预先固定的评分要求，不见条件映射。主代理最后解盲并复核。历史助手答案没有作为基线。

| 类别 | 留出情境的安全概括 | 合成边界情境 | 观察 |
|---|---|---|---|
| 科研 | 如何分析论文写作，暂不分析具体论文 | “写得好”能否推出实验结论正确 | 双方都区分表达和证据，遵守方法讨论范围 |
| 文档 | 准备空表单及分散信息材料，所有个人值改为虚构示例 | 可否将参考报告的数字一起搬入新报告 | 双方都遵循指定内容边界，不把样例数字当目标事实 |
| 工程 | 分析 Git 克隆提前中断的报错，不执行任务 | 只给单次绕过 Git 代理的一行命令 | 双方都保留根因不确定性，命令不改变全局配置 |
| 日常沟通 | 如何在大量目录、文件和引用中找资料 | 长上下文能否直接替代检索 | 双方都说明按需查找，也能区分容量与检索选择 |

**盲评结果：候选胜 0，平局 8，候选负 0。** 四项二元要求（遵从请求、事实依据、实用性、范围边界）在两个条件下均通过。这个小样本没有显示可辨别的额外收益，不能据此宣称两个条件在所有任务上等效。

例如，“长上下文与检索”的新回答中，现有 Context 已经先区分“一次能处理多少内容”和“先找出相关资料”，并说明两者可以配合。追加候选后的答案同样先做这一区分。措辞变化存在，但没有形成需要再加一条规则的证据。

原始对话、确切来源、测试输入、完整新回答、映射和逐题判词都保存在本机忽略目录 `.local/context-evolution/round-002-20261014/`。报告只包含脱敏概括和评价结果。

## 框架这次实际改了什么

1. 支持显式分类划分训练与评估集，同项目或主题族不得跨集合；准备后的输入保存校验值，应用前核对是否被改动。
2. 修正来源识别：AGENTS 包装不作个人表达；复用助手计划记录为当次方案确认；IDE 包装中的同一请求先归一化再去重。粘贴日志等复杂情况仍由语义复核判断。
3. 晋升校验增加真实来源文件匹配、不同用户表达和不同项目或主题族要求。两条重复请求不能充当两次独立支持。
4. 应用时重新校验当前 reflection，避免“先验证通过，再修改内容”绕过检查；决策记录单列补强已有原则，避免与暂缓混在一起。
5. 在进化 Skill 中记录分类对比协议，并修正已安装 Skill 对规范仓库执行契约的路径引用。源 Skill 与本机运行时已同步。

针对来源包装、跨集合泄漏、输入变动、重复支持、伪造文件名、验证后内容变更以及应用/回滚，共 7 项定向测试通过。当前批次还核对了冻结输入、候选和回答文件的校验值。

本轮冻结证据包仍保留原抽取器的标签，7 条有问题的消息由人工式语义审阅排除，没有为让记录好看而重新抽取或改写冻结材料。抽取器修复对后续准备的新批次生效。

## 本轮是否足够好

**作为分类进化流程的一轮验证，完成了预定工作；作为个性化效果的提升，收益仍不足。** 相比上一轮只有留出情境检查，这次真正生成了两种条件的新回答，并增加盲评和来源独立性复核。拒绝重复规则是正确处理，但不能把“没有退步”包装成“更了解用户”。

未能证明内容收益的原因主要有：

- 当前核心与适用 Skill 已覆盖大部分要求，候选的新增信息很少。
- 对话按标题和元数据选择，很多是任务开头，缺少用户纠正、失败后调整及跨项目复现的材料。科研四个对话尤其集中。
- 历史跨度较大，不能直接代表近期全部习惯；原始对话没有全部加载。
- 八个短情境较容易，四个二元维度出现全通过，区分能力有限。
- 生成与评审来自同一模型系列，每个条件每题只采样一次。这是模型文本评估，未运行真实工具任务、长期交互或用户满意度测试。

因此维持 `habits/learned.json` 的空规则集，保留全部判断和证据。下一次更有价值的材料是跨项目的明确纠正，例如用户指出“这不是我想要的”、反复修改同一交付要求，或接受/拒绝某种解释方式；本轮没有擅自启动下一批。

用户可重点判断三件事：三项补强是否准确描述自己；暂缓项里是否有其实希望成为默认行为的要求；目前回答是否仍有经常需要纠正的地方。此报告记录的是系统评估，不替代用户验收。
